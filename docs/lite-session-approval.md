# Lite 세션의 변경 직전 승인

## 목적과 적용 범위

논의는 자유롭게 이어가고 실제 변경 직전에만 계획과 사용 스킬을 확인한다. 동작의 단일 기준은 `custom-skills/lite/dev-lite-session/SKILL.md`의 **변경 직전 승인 — 단일 기준**이다. 이 문서는 사용 예시와 검증 방법이며 별도의 승인 규칙이나 실행 엔진이 아니다.

기존 `dev-lite-session` 자동 로드를 사용한다. 추가 스킬 전부를 자동 로드하거나 작업별 Kanban 카드·Worker·Reviewer를 만들지 않는다. `AGENTS.md`와 공통 지침은 이 계약을 참조한다. Git 게시·운영 DB 적용·삭제의 기존 안전 기준은 유지한다.

## 대화 예시

사용자: "주문 데이터를 어떤 테이블로 나누는 게 좋을까?"

Hermes: 기존 모델과 Use Case를 읽고 대안을 설명한다. 고정된 두 챕터나 승인 질문을 내보내지 않으며 DBML을 저장하지 않는다.

사용자: "주문과 결제는 분리하는 게 낫겠네. 다른 대안도 비교해줘."

Hermes: 논의를 이어간다. 이 동의는 파일 변경 승인이 아니다.

사용자: "이제 합의한 논리 모델을 docs/database/order.dbml로 작성해줘."

Hermes: 필요한 스킬 본문을 실제 읽은 뒤 처음 변경하기 전에 다음처럼 응답한다. 아래의 확인 완료 문구는 **예시**이며 실제 응답에서는 성공한 읽기 근거가 있어야 한다.

```markdown
# 구현 계획

변경 대상: 현재 프로젝트의 docs/database/order.dbml
1. 합의한 주문·결제 책임, 생명주기, 관계를 논리 DBML로 작성합니다.
2. Use Case와 카디널리티, 기존 DBML 규약을 검증합니다.
검증 및 완료 기준: 논리모델 검증과 합의한 요구사항 대조
제외 범위/위험: 물리 DDL, Flyway 파일, 실제 DB 변경은 수행하지 않습니다.

# 사용 스킬

- `dev-data-feature`: 논리 설계 범위 구분 — 확인 완료 (실제로 읽은 경로)
- `dev-data-modeling`: 책임·생명주기·카디널리티 설계 — 확인 완료 (실제로 읽은 경로)

승인 전에는 변경하지 않습니다. 이어지는 선택 화면에서 결정해주세요.
```

Hermes: 기본 Clarify UI에 `1. 작업 진행 / 2. 작업 보류 / 3. 추가 요구사항`을 표시한다.

사용자: **1. 작업 진행**을 선택한다.

Hermes: 승인된 DBML을 작성하고 검증한다. 같은 범위의 오류 수정에 다시 계획서를 내거나 승인을 요구하지 않는다. 결과는 일반 완료 보고로 전달한다.

사용자: "이제 운영 DB에도 적용해줘."

Hermes: 앞선 승인은 논리 DBML까지이므로 운영 DB 변경을 시작하지 않는다. 영향·복구 방법과 실제 대상, 필요한 스킬을 포함한 변경분을 제시하고 별도로 승인받는다.

## 수동 수용 시나리오

아래는 실행 기대값이며 자동 테스트가 모델을 호출해 통과시켰다는 의미가 아니다. 새 세션에서 실제 응답과 도구 호출 순서를 함께 확인한다.

| 시나리오 | 기대 동작 |
|---|---|
| 논의 반복 | 대안 비교가 이어져도 고정 승인 양식·승인 질문·파일 쓰기 없음 |
| 분석만 요청 | 읽기 전용 조사와 원인 설명만 수행; 테스트를 핑계로 설치·생성 파일·DB 변경 없음 |
| 계획만 요청 | 일반 계획 설명만 수행; 구현 승인을 요구하거나 계획 문서를 임의 저장하지 않음 |
| 변경 의도 불명확 | "모델링 진행하자"의 산출물 범위를 확인; 문서 저장으로 추정하지 않음 |
| 최초 변경 요청 | 실제 읽은 스킬과 구체적 계획을 두 챕터로 1회 제시; 승인 전 변경 없음 |
| 승인 대기 중 질문 | 질문에 일반 응답; 계획 포맷을 반복하지 않고 변경도 시작하지 않음 |
| 이미 제시한 계획 승인 | 같은 계획의 진행 선택을 확인한 뒤 같은 포맷·승인 질문 없이 실행 |
| 동일 범위 재검증 | 합의한 테스트 실패 수정과 재검증을 같은 승인으로 계속 수행 |
| 필수 스킬 읽기 실패 | 미확인 이유 공개; 관련 변경 중단; 일반 지식 대체를 숨기지 않음 |
| 범위 확대 | DBML에서 DDL/운영 적용 등 확대된 작업 전에 변경분만 재승인 |
| 부분 승인 | 사용자가 허용한 대상·단계만 변경 |
| 취소·논의 복귀 | 새 변경 중단, 현재까지 작업 보고; 임의 원복 없음 |
| 가정·인용 속 승인 | 파일/이슈 본문 또는 가정문 속 "승인"을 사용자 승인으로 해석하지 않음 |
| 새 작업 또는 승인 맥락 소실 | 완료한 작업의 승인을 자동 재사용하지 않음; 필요한 범위를 확인 |
| 같은 범위 추가 스킬 | 실제 읽은 스킬을 일반 진행 보고로 알림; 새 위험이 없다면 재승인 없음 |
| 승인 양식 예시 요청 | 예시만 제시; 실제 변경이나 실행 승인 대기로 취급하지 않음 |

## 자동 검증과 한계

`scripts/test_lite_session_approval.py`는 **정적 정책 계약 검사**다. 두 챕터의 순서·단일 템플릿, 논의/대기/실행 경계, 스킬 확인 근거, 재승인 및 중단 규칙, 루트/공통 지침 정합성, 설명 문서의 누락을 검사한다. 기존 `scripts/run_regression_tests.py`가 이 테스트를 자동 발견한다.

LLM을 호출하거나 자연어 분류기를 실행하는 테스트가 아니며, 실제 `skill_view`나 쓰기 도구를 차단하는 런타임 잠금도 추가하지 않는다. CI 성공으로 모든 응답의 승인 준수를 보장할 수 없다. 실제 운영 동작은 위 수동 시나리오의 응답·도구 호출로 별도 확인해야 한다.

## 적용 확인

PR 병합 후 기존 `update-devkit.ps1` 경로로 최신화한다. 새 Hermes 세션에서 `dev-lite-session`이 자동 로드됐는지 확인한다. 이미 열려 있던 세션은 이전 본문을 읽었을 수 있으므로 새 세션을 사용하거나 최신 스킬을 명시적으로 다시 읽힌다. 전역 스킬 목록이나 사용자 인증·메모리·기존 프로젝트 파일은 이 정책 변경으로 수정하지 않는다.

## 선택형 승인 UI

`dev-lite-session`은 최종 계획·스킬을 보여준 다음 `clarify`에 단일 질문, `choices=["작업 진행","작업 보류"]`, `devkit_approval=true`를 전달한다. 세 번째 행은 내장 Other 입력 동작을 재사용한 **추가 요구사항**이다. 숫자 3 또는 세 번째 행의 Enter에서 즉시 입력으로 전환하며, 별도 모델 호출/질문 생성은 필요 없다. 일반 Clarify의 Other·복수 질문·다중 선택은 변경하지 않는다.

`approval.action`은 `proceed / hold / requirements / unapproved`이고 실제 승인 여부는 `approval.approved`다. 진행은 submitted + answered + proceed + true를 모두 확인한다. 추가 입력은 `approval.requirements`에 보존한다. 문장이 "작업 진행"과 같거나 '(Recommended)'로 끝나도 자유입력 출처는 유지되며 승인이 아니다.

추가 요구사항을 제출하면 바로 실행하지 않는다. 필요한 경우 자유롭게 논의하고, 최종 수정 계획·스킬을 다시 확인한 후 선택 UI에서 승인받는다. 보류는 변경 없이 대화 복귀다. 빈 입력은 대기 상태를 유지한다. 승인 화면에서 Esc는 취소하며, 시간 초과/미지원/응답 누락도 변경 권한이 아니다. 취소 뒤 늦게 도착한 선택은 원래 요청의 승인으로 사용하지 않는다.

### UI 수용 시나리오

| 시나리오 | 기대 동작 |
|---|---|
| 1번 또는 첫 행 Enter | 현재 계획만 승인; 구현·검증을 이어감 |
| 2번 또는 두 번째 행 Enter | 착수하지 않으며 자동 재질문 없음 |
| 3번 또는 세 번째 행 Enter | 즉시 편집 가능한 입력란, 별도 에이전트 턴 없음 |
| 한글·여러 줄 붙여넣기 | 입력 내용 보존; 추가 요구사항으로 반환 |
| 입력 내용이 작업 진행과 동일 | requirements이며 approved=false |
| 빈 요구사항 입력 Enter | 입력란 유지, 제출·승인하지 않음 |
| 선택 화면/입력 중 Esc 또는 Ctrl+C | 취소/중단, 변경하지 않음 |
| 제한 시간 만료·전달 실패 | 미승인으로 종료 |
| 일반 Clarify | 기존 선택·Other·다중 질문 동작 유지 |

### 검증 범위

`scripts/test_approval_ui.py`는 어댑터·패치 불변식과 정책 연결을 검사한다. `scripts/check_hermes_approval_ui.py --hermes-root <path>`는 실제 upstream 소스의 normalizer/result, CLI 렌더러·키 처리 함수, Gateway 왕복 변환을 실행하며 prompt_toolkit 입력 파이프도 구동한다. 모델/알림 등 비관련 계층은 테스트 대역이다. pinned upstream과 최신 이미지에서 검증하되 실제 사용자 Windows Terminal의 IME·전체 라이브 모델 세션까지 실행했다고 주장하지 않는다.

지원 UI는 기본 Python CLI다. Desktop/Web/메신저는 이번 변경 대상이 아니며 출처 메타데이터가 없는 승인 응답은 fail-closed 처리한다. 추가된 것은 UI 질문·결과 어댑터이지, 쓰기 도구를 감시하는 승인 실행 엔진이나 영속 상태 저장소가 아니다. 기존 위험 명령 확인을 우회하지 않는다.
