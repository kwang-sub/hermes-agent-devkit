# 자연스러운 한국어 작성 기준

문체의 최우선 기준은 **독자가 실제 업무에서 사용하는 말로 자연스럽게 쓰는 것**이다. 단어를 어렵게 바꾸거나 설명을 길게 늘려 전문성을 흉내 내지 않는다. 사실과 의미를 보존하는 범위에서 표현을 다듬는다.

## 기준 선택

사용자가 지정한 문체·용어 → 대상 문서의 승인된 양식·용어집 → 사용자가 제공한 작성 예시 → 이 기준 순으로 따른다. 기존 문장도 이미 자연스러우면 그대로 둔다. 사용 빈도를 조사하지 않았다면 어떤 표현이 통계적으로 더 흔하다고 주장하지 않는다.

- 고객 안내문: 정중하고 직접적인 `합니다`체. 필요한 행동과 조건을 먼저 쓴다.
- 내부 기술 문서: `한다`체 또는 기존 문체. 담당 주체, 처리 조건, 결과를 분명히 쓴다.
- 보고서·제안서: 확인한 사실, 제안, 기대 효과, 미확인 사항을 구분한다. 효과를 보장하지 않는다.
- 발표 자료·표: 제목과 항목명은 짧게 쓰되 조건과 단위를 생략하지 않는다. 짧은 제목에 완결 문장을 강제하지 않는다.
- 다른 언어의 문서에는 한국어 어휘 교정을 강제하지 않는다. 원래 언어와 사용자가 요청한 문체를 유지한다.

## KO-01: 사실과 의미를 먼저 보존한다

수치·단위·날짜·범위·주체·부정·예외·의무 수준을 바꾸지 않는다. `할 수 있다`를 `한다`, `권장`을 `필수`, `미확인`을 `정상`으로 바꾸지 않는다. 분명하지 않은 주체나 이유는 만들어 채우지 않는다. 알 수 없는 내용은 원문을 유지하거나 미확인으로 표시한다.

API 경로, 필드명, 코드, 명령어, 설정 키, 수식, 데이터 값, 제품명, 인용문, 계약·규정의 원문은 보호한다. 주변 설명만 고친다. 원문 자체를 바꾸는 별도 요청이 있으면 변경 범위를 다시 확인한다. 비밀값과 개인정보를 예문에 복사하지 않는다.

## KO-02: 익숙하고 구체적인 말을 쓴다

`진행을 수행한다`보다 `진행한다`, `확인이 가능하다`보다 `확인할 수 있다`처럼 자연스럽게 쓴다. 설명에 필요한 `트랜잭션`, `멱등성`, `확장성`, `최적화` 같은 전문 용어는 유지한다. 독자에게 낯선 용어만 처음에 간단히 설명한다.

`혁신적`, `획기적`, `극대화`, `고도화`, `원활한`, `유연한`, `최적의`, `레버리지`는 문맥을 살펴볼 표현이지 금지어가 아니다. 정확한 의미나 근거가 있으면 사용한다. 같은 뜻을 반복하는지, 무엇이 달라지는지 설명하지 않고 평가만 붙였는지 확인한다. **금지어 목록에 따른 자동 치환이나 단어 개수로 합격을 판정하지 않는다.**

## KO-03: 번역투와 불필요한 명사 표현을 줄인다

`~에 대한 처리를 수행한다`, `~를 통해 ~를 제공한다`, `~에 있어서`를 습관적으로 반복하지 않는다. 주체와 동작이 확인되면 직접 쓴다. 주체가 불명확한 문장을 능동형으로 바꾸려고 담당자를 만들어내지 않는다. 모든 피동문이나 한자어를 없애는 규칙은 아니다.

## KO-04: 추상적인 칭찬 대신 확인한 내용을 쓴다

`사용자 경험을 혁신한다`, `효율성을 극대화한다`처럼 근거 없는 평가를 넣지 않는다. 원문에 있는 기능·수치·변경 내용을 설명한다. 구체적인 근거가 없으면 표현을 줄이거나 미확인임을 남긴다. 자연스럽게 보이게 하려고 성과, 사례, 사용자 반응을 추가하지 않는다.

## KO-05: 문서에 필요한 만큼만 구성한다

긴 도입, 앞 내용을 반복하는 결론, 의미 없는 `또한/나아가/궁극적으로`, 기계적인 세 항목 구성을 줄인다. 문단·표·목록은 정보에 맞게 선택한다. 모든 문장을 짧게 끊거나 일정한 길이로 맞추지 않는다. 과도한 굵게 표시·장식·이모지를 피하되 경고와 핵심 조건의 강조는 유지한다.

`이제 살펴보겠습니다`, `좋은 질문입니다`, `도움이 되었기를 바랍니다` 같은 대화 문구를 제출 문서에 넣지 않는다. 검토 과정, 스킬 실행 기록, 초안과 최종본의 중복을 결과물에 섞지 않는다.

## KO-06: 사람처럼 보이기 위한 연출은 하지 않는다

친근함을 이유로 반말, 농담, 감상, 가짜 경험·의견, 고의적인 오탈자나 어수선한 구성을 넣지 않는다. 자연스러운 문어체도 허용한다. AI 탐지기 점수나 탐지 회피를 목표로 삼지 않는다. 작성자나 검토자가 실제 사람이라고 꾸미지 않는다.

## KO-07: 표현과 용어를 일관되게 유지한다

같은 대상을 `콜백 서버/응답 처리 장치/결과 전달 플랫폼`처럼 번갈아 부르지 않는다. 반복을 피하려다 의미가 달라지는 동의어를 쓰지 않는다. 사용자 용어집과 기존 문체를 유지하고, 어색한 부분만 최소한으로 수정한다.

## 검토 순서

원문과 근거 확인 → 초안 작성 → 어휘·문장·구성 검토 → 원문과 의미 대조 → 파일 출력 후 다시 확인 순으로 진행한다. 검토는 현재 세션에서 수행하며 별도 Reviewer나 승인 단계를 만들지 않는다. 수정이 필요하지 않은 문장은 보존한다.
