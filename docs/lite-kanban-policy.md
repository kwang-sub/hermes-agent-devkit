# Hermes Lite의 Kanban 사용 정책

## 실행과 기억을 분리

Hermes Lite의 작업은 **대화 → 소스 수정 → 테스트 → 사용자 리뷰**가 기본이다. Kanban은 실행 조건이 아니며 작업 ID, 상세 인계, Coder/Reviewer ownership 계약이 없어도 시작한다.

### 기록하는 경우

| 상황 | 권장 처리 |
|---|---|
| 짧은 버그 수정·즉시 완료 | Kanban 기록하지 않음 |
| 여러 날 이어질 작업 | 사용자에게 카드 기록 여부 제안 |
| 해결되지 않은 오류/차단 | 원인·다음 확인 단계만 기록 |
| 추후 개선할 기술 부채 | 별도 TODO 카드 |
| 주요 설계 결정 | 해당 프로젝트 기존 카드 갱신 가능 |
| Standard가 실행 중인 카드 | **읽기만** 하고 claim/status는 변경하지 않음 |

### 간결한 기록 템플릿

- **목적:** 무엇을 해결하려고 했는가
- **완료:** 구현된 것, 관련 Git 커밋
- **남은 문제:** 재현 조건·차단 원인
- **다음 작업:** 다음 세션에서 바로 시작할 구체적인 행동
- **검증:** 실행한 테스트와 결과

코드 상세는 Git diff/commit이 authoritative하며, Kanban에 변경 파일 전체·세션 로그·토큰 사용 기록을 반복해서 복사하지 않는다.

## 사용 예시

- "HDC-218의 남은 API 경로 호환성 이슈만 기존 Kanban 카드에 기록해 줘."
- "기존 HDC-218 카드의 미완료 사항을 알려 줘. 아직 카드 상태를 변경하지 마."
- "이 변경은 완료했으니 관련 테스트와 Git 커밋을 기존 카드에 메모해 줘."
- "Kanban에는 남기지 말고 지금 코드를 먼저 수정해 줘."

## 실패 시

- Kanban 조회/기록 도구 오류가 생겨도 일반 소스 분석과 테스트는 계속 진행한다.
- 단, 사용자가 요청한 기록이 실패했으면 **기록 완료라고 말하지 않는다**.
- 기존 카드에 owner claim이 있으면 Lite에서 재할당/완료 처리하지 않는다.
- 알림은 기존 옵션의 이벤트에 대해서만 작동한다. Lite가 별도 알림 트리거를 새로 생성하지 않는다.

## Standard 복귀

Lite에서 직접 만든 카드가 있더라도 Standard가 무조건 작업 인계 계약을 가진 것으로 간주하지 않는다. Standard dispatch를 원할 때는 기존 Orchestrator 규칙으로 명세와 승인 조건을 별도 검토한다.
