# 포맷별 실행 기준

정책은 `dev-document-author`, 실제 파일 작업은 설치된 공식 스킬이 담당한다. 아래 이름은 확인할 후보이며 설치·가용성·기능을 보장하는 목록이 아니다.

| 요청한 출력 | 사용할 실행 방법 | 확인할 사항 |
|---|---|---|
| Markdown / TXT / 대화 안의 문장 | 현재 파일 도구 또는 응답 | UTF-8, 기존 구조와 요청한 변경 범위 |
| DOCX | `microsoft-office`의 Word 참조 | 실제 생성·편집·템플릿·검증 기능 |
| PPTX | `microsoft-office`의 PowerPoint 참조 | 슬라이드 구성·노트·렌더링 기능 |
| XLSX / CSV | `microsoft-office`의 Excel 참조 | 수식·셀 값·시트·인코딩·재계산 지원 |
| PDF 신규 생성·기존 PDF 작업 | `pdf` | 생성·읽기·편집·렌더링 지원 범위 |
| DOCX / PPTX / XLSX → PDF | `microsoft-office`의 변환 안내 | 변환기·글꼴·인쇄 영역·출력 검증 |

## 실행 전 확인

실행할 환경에서 스킬 목록을 조회하고 `skill_view`로 본문과 필요한 포맷 참조를 실제로 읽는다. 저장소의 최신 문서나 `related_skills`만 보고 설치됐다고 판단하지 않는다. 명령과 파일 경로는 실제 읽은 스킬에서 찾으며 `/opt/hermes`나 개인 프로필의 스킬 위치를 추정해 고정하지 않는다.

공식 스킬이 요구하는 실행 도구·Python 환경·라이브러리·변환기·글꼴을 읽기 전용으로 확인한다. 이름만 비슷한 구버전 스킬을 자동 별칭으로 취급하지 않는다. 본문을 확인하지 못했으면 실행하지 않는다.

필수 기능이 없으면 **해당 출력만 미완료**로 보고한다. 가능한 본문 작성이나 다른 요청 포맷은 별도로 완료할 수 있다. 의존성 설치·공식 스킬 초기화·Hermes 업데이트·외부 서비스 업로드는 자동으로 하지 않는다. 대안이 작업 범위나 위험을 바꾸면 변경분을 승인받는다.

## 변환과 재작성은 구분한다

DOCX/PPTX/XLSX 파일의 레이아웃을 유지하는 PDF 변환은 설치된 변환 도구가 필요하다. 도구가 없으면 변환이 불가능하다고 명시한다. 내용으로 PDF를 새로 만드는 방법은 별도 대안이며, 사용자 동의 없이 동일한 변환 결과로 대체하지 않는다.

여러 출력물은 같은 승인 내용에서 만든다. 표·목차·각주·링크·페이지 분리·한글 글꼴을 비교한다. 변환 도구가 글꼴을 대체할 수 있으므로 실제 렌더링으로 확인하지 않은 레이아웃을 정상이라고 보고하지 않는다.

## 편집 보호

글을 자연스럽게 다듬는 대상은 설명문·제목·항목명이다. XLSX의 수식·셀 값·이름 정의·숫자 형식, CSV의 데이터, API 예제·필드명은 문체 교정 대상으로 삼지 않는다. 수식 계산 결과를 확인하지 않았다면 검증 완료로 표시하지 않는다.

HWP/HWPX, 구형 DOC/PPT/XLS, 기타 목록에 없는 형식은 지원을 가정하지 않는다. 가능한 별도 스킬·변환 경로와 손실 위험을 확인한 뒤 범위를 정한다. 확장자만 바꾸어 다른 형식인 것처럼 제공하지 않는다.

## 결과 판정

공식 도구가 종료 코드 0을 반환해도 `rendered: false`, `missing`, `skipped` 등 실제 결과를 확인한다. 출력 파일이 있고 다시 읽을 수 있는지, 요청한 내용이 들어 있는지 확인한다. 시각 검증·수식 검증·변환 검증을 못 했으면 각각 미검증으로 보고한다. 도구별 결과 필드는 설치 버전의 안내를 따른다.
