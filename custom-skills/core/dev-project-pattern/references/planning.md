# 복잡한 작업의 선택적 계획

명시적 계획 요청 또는 위험이 큰 변경에서만 목표·범위·제외 범위·현재 근거·변경 순서·최소 검증·위험/복구를 정리한다. 계획 요청을 구현 승인으로 보지 않는다.

화면 → 기능 요구 → 도메인 책임 → 논리 데이터 관계 → Use Case 검증 → API 계약 → 구현 순서는 설계 근거를 확인하기 위한 것이며 고정된 카드/승인 루프가 아니다. 기존 프로젝트 규약이 우선이다. 논리 설계와 실제 schema 적용의 권한은 분리한다.

작은 수정은 해당 코드·테스트만 확인한다. 필요한 스킬 목록을 모두 고정하거나 전체 repository를 반복 분석하지 않는다.
