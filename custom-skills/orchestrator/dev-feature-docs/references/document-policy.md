# 기능 문서 작성·수정 정책

## 논의와 기록

문서화 요청 전 논의는 파일을 바꾸지 않는다. 이미 제공된 목적·제약을 다시 질문하거나 고정된 수의 질문을 강제하지 않는다. 요청한 부분을 작성할 수 있으면 작성하고 부족한 부분은 미정으로 남긴다. 문서화 승인이 구현 승인으로 전파되지 않는다.

사용자가 말한 사실·결정과 에이전트 제안을 구분한다. 채택되지 않은 제안을 합의된 구현 범위로 승격하지 않는다. 전체 PRD, 일정, 수치 KPI, 의무적인 스토리 분해, 신규 Task는 요구하지 않는다.

## 문서의 책임

기능 문서는 목적·사용자 기능·완료 기준·현재 구현 확인을 소유한다. 화면별 버튼/노출/입력/상태 상세는 실제 `screen-spec.md`, API 상세는 기존 API 문서를 참조한다. 단지 파일명 관례만으로 존재하지 않는 참조를 만들어 넣지 않는다.

`docs/features/README.md`는 선택적인 링크 목록이다. 목록 누락 때문에 문서 확인을 실패 처리하지 않는다. 목록에 상태를 복제하거나 별도 `features.json`/registry/관계 DB를 만들지 않는다.

## 안전한 부분 수정

1. 요청과 승인된 변경 범위를 먼저 확인한다.
2. 쓰기 직전에 현재 파일을 다시 읽는다. 논의 때 읽은 오래된 사본으로 덮어쓰지 않는다.
3. 이번 변경과 무관한 내용·사용자 편집·미정 사항·과거 완료 범위를 보존한다.
4. 요청한 섹션/항목만 수정하고 중요한 결정 변경 이유를 기록한다.
5. read 이후 변경 감지 또는 충돌이 있으면 재확인한다. 안전한 병합이 불명확하면 덮어쓰지 않고 문서 반영 미완료를 보고한다.

기존 문서를 템플릿으로 전체 교체하지 않는다. 새 범위 채택은 명시적 사용자 결정이나 해당 범위를 포함한 기존 계획 승인이 있어야 한다. 새 범위가 실제 착수 전이면 `계획 중`, 착수 후면 `진행 중`으로 재판단하며 기존 완료 기록은 남긴다. 후속 아이디어만 추가하면 이전 완료 상태를 유지한다.

여러 작업이 같은 기능 문서를 다루면 전체 완료 판정 전에 최신 본문과 남은 범위를 다시 읽는다. 자기 Task가 성공했다는 이유로 다른 항목의 체크박스를 변경하지 않는다.

## 상태 확인의 판단표

| 관찰 | 문서 처리 |
|---|---|
| 논의/계획/승인/카드 생성만 존재 | 진행 중으로 전환하지 않음 |
| 실제 구현 착수 확인 | 해당 범위의 진행 중 반영 |
| 합의된 범위 일부만 구현·검증 | 진행 중 유지, 확인된 항목과 남은 범위 기록 |
| 합의된 범위 전체를 현재 코드 기준의 근거로 확인 | 구현 완료 |
| 테스트 성공이나 Task DONE만 존재 | 전체 완료의 충분조건으로 취급하지 않음 |
| 기존 완료 + 향후 아이디어 추가 | 구현 완료 유지 |
| 참고용 문서를 읽은 리팩터링/빌드 수정 | 상태 변경 없음 |
| 근거 부재/오래된 테스트/다른 브랜치 결과 | 마지막 확인 기준을 보존하고 현재 미확인 부분 보고 |
| 문서가 없거나 쓰기 실패 | 구현 결과 유지, 문서 반영 미완료 보고 |

새로운 enum은 만들지 않는다. `미확인`, `반영 미완료`는 상태가 아니라 확인 결과다. `구현 완료`는 merge/deploy 여부가 아니다. branch/commit 또는 Non-Git 파일·관찰 시점 등 실제 확인 기준을 기록한다. 단순 branch 이름만으로 테스트 결과가 최신이라고 추정하지 않는다.

## 근거 재사용

기존 Standard Flow의 코드 변경 목록, 승인 범위, 테스트 결과, Reviewer 결과 중 실제로 확보한 것만 사용한다. 실행하지 않은 테스트는 PASS라고 적지 않는다. 부분 검증·미실행 테스트·환경 제약을 구분한다. 완료 결과가 현재 코드 또는 문서 범위에 대응하지 않으면 완료로 추정하지 않는다.

문서 상태만 확인하기 위해 새 CI, 테스트 명령, 모델 호출 파이프라인, 재승인, Reviewer를 만들지 않는다. 추가 검증이 필요한 실제 구현 문제는 기존 Flow 절차를 따르고 문서 문제와 구분한다.

## 예시: 일부 구현

문서 범위가 CAGR/MDD/샤프 지수이고 이번 Task가 MDD만 완료되었다면 MDD만 확인 기록을 남긴다. 나머지 항목이 남아 있으면 기능 상태는 진행 중이다. 미래의 세금 분석 아이디어는 이 판단에서 제외한다.
