# DevKit 명칭과 기존 설정 전환

현재 실행 방식은 `default` 세션의 직접 개발 하나다. 시험 운영 때 사용한 Lite 명칭을 사용자 안내, 스킬 이름, 실행 파일과 CI에서 제거했다. 승인 절차, 직접 개발, 선택적 Kanban과 문서 작성 기능은 그대로 유지한다.

## 변경한 이름

| 이전 | 현재 |
|---|---|
| `dev-lite-session` | `dev-session` |
| `dev-lite-review` | `dev-review` |
| `custom-skills/lite/` | `custom-skills/core/` |
| `scripts/init-lite.ps1` | `scripts/init-devkit.ps1` |
| `scripts/lite_default_profile.py` | `scripts/devkit_default_profile.py` |
| `018-devkit-lite-init` | `018-devkit-init` |
| `/run/devkit-lite-ready` | `/run/devkit-ready` |

`core`는 세션·Git·작업 공간 관리 스킬, `shared`는 Java·DB·문서 작성 등 전문 스킬을 보관하는 폴더다. 실행 모드를 구분하지 않는다. 자동으로 읽는 기본 스킬은 `dev-session` 하나이며, 나머지는 해당 작업에 필요할 때만 읽는다.

## 업데이트 동작

기존 `update-devkit.ps1`을 그대로 사용한다. 별도 전환 명령, 설정 초기화, 새로운 서비스나 마운트는 필요하지 않다. 업데이트 전에 진행 중 작업을 마무리한다. 실제 설정 변경은 기존과 같이 컨테이너 서비스가 시작되기 전에만 수행한다.

설정의 `skills.auto_load`에 있는 두 옛 스킬명은 새 이름으로 바꾸고 중복을 제거한다. `skills.external_dirs`는 현재 설정된 custom-skills 경로와 기본 `/opt/custom-skills` 아래의 `lite` 경로만 `core`로 바꾼다. 사용자 개인 경로(`/personal/lite` 등), 추가 스킬, 모델, 인증, 메모리, 세션과 그 밖의 설정은 보존한다. 알 수 없는 과거 custom-skills 루트를 추측해 바꾸지 않는다.

새 설정을 다시 읽어 확인하며, 두 번째 업데이트에서는 같은 내용을 반복 기록하지 않는다. 새 이름이 반영된 뒤에는 새 Hermes 세션을 시작한다. 이미 열려 있는 세션이 기억한 스킬 이름과 본문은 자동 갱신된 것으로 간주하지 않는다. 옛 이름의 중복 스킬이나 별도 실행 모드는 등록하지 않는다.

읽기 전용 상태 확인:

```powershell
.\scripts\init-devkit.ps1 -Mode status
```

`plan`과 `status`는 새 상태 폴더나 잠금 파일을 만들지 않는다. 호스트의 `plan`은 새 스크립트 전체를 이미지의 Python에 전달하므로, 빌드 전 옛 이미지 안에 새 파일명이 없어도 검사할 수 있다.

## 기존 기록을 보존하는 방법

새 백업·전환 기록·역할 보관은 `/opt/data/devkit-state/`에 만든다. 기존 `/opt/data/devkit-lite/`의 백업, 완료 기록과 보관된 역할은 원래 위치에 남긴다. 파일 내용이나 기록에 적힌 과거 백업 경로를 새 이름으로 치환하지 않는다.

두 위치의 전환 기록을 모두 확인한다. 어느 쪽이든 `prepared`, 알 수 없는 상태·스키마, 잘못된 파일 구조나 심볼릭 링크가 있으면 쓰기 전에 중단한다. 새 기록이 정상이라는 이유로 과거에 중단된 작업을 무시하지 않는다. 같은 역할의 보관본이 두 위치에 있거나 활성 역할과 보관본이 충돌하면 자동 병합하지 않는다.

옛 overlay 기록(schema 1/2)은 현재 설정이 기록의 관리 항목과 일치할 때만 새 private backup으로 옮긴다. 사용자 설정이 달라졌으면 자동으로 덮어쓰지 않는다. 기존 상태 폴더가 있으면 이전 잠금과 새 잠금을 함께 사용하고, 새 설치에는 옛 폴더를 만들지 않는다. 실패 시 이번 작업의 변경만 원복하고, 중간 종료 기록은 수동 복구를 위해 남긴다.

## 옛 명칭을 남긴 곳

이 문서, 과거 설정을 읽는 호환 코드, 이전 버전 그대로의 테스트 자료에만 옛 명칭을 남긴다. 폐기한 `updatekit_lite.ps1`·`updatekit_lite.sh`·루트 `init-lite.ps1`이 다시 생기지 않도록 검사하는 코드도 유지한다.

승인 UI의 내부 wire ID `lite_change_approval_v1`은 기존 CLI/Gateway 통신 호환을 위해 유지한다. 사용자에게 표시되는 명칭이나 실행 모드가 아니다. 승인 판단 방식과 프로토콜을 이번 이름 변경에서 바꾸지 않는다. 밝은 화면 테마를 뜻하는 ‘라이트 모드’와 SQLite 등의 다른 용어도 변경하지 않는다.

## 검증 범위

정적 검사는 옛 활성 경로·표시 이름이 다시 추가되는지와 스킬 참조를 확인한다. 파일시스템 테스트는 이전 default 설정 전환, 사용자 설정·과거 백업 보존, 두 번 적용, 실패 시 원복, 구·신 상태 충돌과 잠금을 검사한다.

기존 전체 회귀와 Windows updater 검증을 유지한다. 실제 이미지 검사는 새 설치, 이전 역할 기반 환경, 이전 default 환경, 실행 중 작업, 구·신 보관 경로 충돌, 과거 미완료 전환 기록을 가진 임시 컨테이너에서 수행한다. 테스트 성공을 사용자 PC의 업데이트 완료로 보고하지 않는다.
